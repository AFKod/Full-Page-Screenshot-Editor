# Результаты проверки

Проверено 17 октября 2026 года, версия 1.0.2. Ниже перечислены реально выполненные проверки, а не план тестирования.

## Автоматические проверки исходников

`node scripts/check.mjs` — **PASS**:

- Manifest V3, module service worker, наличие ресурсов и PNG-иконок.
- Только `activeTab`, `scripting`, `clipboardWrite`; постоянных host permissions нет.
- Синтаксис всех 16 файлов JavaScript / MJS, включая тесты и инструменты проверки.
- Уникальность HTML id, ссылки JS на элементы редактора, отсутствие inline script.

`node --test tests/*.test.js` — **23 / 23 PASS**:

1. План прокрутки, начало/конец и отсутствие повторного последнего кадра.
2. Непрерывные границы кадров при дробном DPR.
3. Область Crop, пересекающая шов двух кадров.
4. Выделение в обратном направлении и ограничение координат.
5. Перемещение, resize и пересечение границ маркерами.
6. Соответствие экранных координат пикселям после обрезки при разных масштабах.
7. Огромная двумерная область: покрытие частями без пропусков и перекрытий.
8. Сохранение маленькой области одним файлом без изменения разрешения.
9. Планирование captureVisibleTab с соблюдением двух вызовов в секунду.
10. Одинаковый масштаб осей при округлённой физической высоте viewport.
11. Точное локальное декодирование PNG data URL без fetch под строгой CSP.
12. Регрессия масштаба Windows 150%: расчётный край на один пиксель больше последнего PNG. Тест подтверждает, что условие ошибки версии 1.0.0 воспроизводится, а новый план собирается полностью.
13. Округление viewport шириной 4K не меняет подтверждённый масштаб DPR 1,5.
14. Масштаб при включённой/исключённой из PNG классической полосе прокрутки.
15. Дробный `visualViewport` и корректное исключение полосы прокрутки из кадра.
16. Матрица 12 масштабов × 3 длины (до 100 003 CSS px) × 3 вариантов округления: валидные исходные координаты и однократное покрытие каждого пикселя результата.
17. Существенное отсутствие нижнего содержимого и внутренние пропуски по-прежнему отклоняются.
18. Небольшие различия округления между колонками не создают щелей.
19. Поток PNG: CRC каждого блока, IHDR, RGB8, точное восстановление строк через независимую zlib-декомпрессию.
20. Один PNG высотой 70 000 px без ограничений Canvas; проверены заголовок, число и содержимое строк.
21. Один PNG шириной 40 000 px, несколько IDAT-блоков, непрерывный deflate-поток и точные пиксели.
22. Отмена и ошибки поставщика строк, нехватка/избыток/обрыв строк: частичный файл не возвращается.
23. Размеры пользователя проходят бюджет одного JPEG; буферы PNG-полос ограничены для разных ширин.

`npm run build` вызывает тот же `scripts/check.mjs`. Трансляции/упаковки для запуска нет: рабочие исходники уже являются сборкой расширения.

## Реальный Chrome

Google Chrome **155.0.8059.80**, macOS, headless, отдельный временный профиль. Текущий прогон 1.0.3 при DPR 1,25 — **26 / 26 PASS**. Использован установленный Chrome через Playwright. Расширение загружалось с исходным manifest через CDP `Extensions.loadUnpacked`, а `Extensions.triggerAction` запускал настоящую action и выдачу `activeTab`. Тестовая подмена manifest или дополнительных разрешений не применялась.

Последний прогон: [test-results/browser-report.json](test-results/browser-report.json). Сохранённые предыдущие прогоны 1.0.1: [DPR 1,25](test-results/browser-report-dpr125.json) и [DPR 1,5](test-results/browser-report-dpr150.json).

В предыдущей версии 1.0.1 прогон при DPR **1,5**, окне **2560 × 1440 DIP** (рендер шириной 3840 физических пикселей) — **16 / 16 PASS**, включая публичную страницу **https://pipl.io/** при зуме Chrome **100%**. Получен снимок **3840 × 16816 px**, 9 кадров. В этом реальном захвате CSS-оценка высоты дала 16817 px, а последний PNG покрывал до 16816 px: старой проверке требовалась строка 2031 при фактической высоте PNG 2030. Новая склейка согласовала внешний край на 1 px. Зафиксированная геометрия включена в регрессионный тест, исправление сохранено в 1.0.2.

При загрузке публичной страницы один внешний ресурс сообщил `ERR_CERT_AUTHORITY_INVALID`; захват завершился. Полное визуальное совпадение содержимого с компьютером пользователя не проверялось.

- Захват через настоящие `chrome.scripting` и `chrome.tabs.captureVisibleTab`, последующее открытие редактора.
- Длинная страница 3500 CSS px при **нативном DPR 1,25**: результат **1600 × 4375 px**, правильные цвета разделов и швы. Панель прогресса отсутствует на снимках.
- Восстановление обеих прокруток, исходных CSS-значений, fixed/sticky и атрибута `loading` после успеха.
- Выделение мышью, редактирование точных координат, неизменность координат при масштабе 50%, подтверждение Crop.
- Реальные загрузки **PNG и JPEG 400 × 300 px**; проверены размеры декодированных файлов.
- Успешная запись PNG в системный буфер через кнопку редактора.
- Отмена через Esc во время предзагрузки, восстановление страницы и пояснение в редакторе.
- Повторный захват при **зуме Chrome 125%**, DPR становится **1,5625**; масштаб кадра определён как **1,5625**, геометрия не искажена.
- Искусственная ошибка второго вызова captureVisibleTab после одного успешного кадра: состояние страницы восстановлено, ошибка отображена, частичные кадры удалены. Подменялся только API в памяти тестового worker; production-файлы не менялись.
- После ошибки скачан JSON диагностики с размерами viewport и последнего кадра.
- Регрессия: в памяти worker тест обрезал возвращаемые PNG на 2 физические строки. Захват успешно склеен, последняя строка содержит ожидаемый пиксель нижнего бордера, внешняя граница корректируется в пределах допуска; пиксели не растягиваются. Это искусственное воспроизведение округления, а не запуск Windows.
- Синтетическое локальное изображение **64 × 20 000 px**, составленное из 20 PNG-кадров: обычное «Сохранить» скачивает **один PNG 64 × 20 000**; панель частей не появляется. Явная кнопка «Частями» создаёт прежние 3 части; последняя часть **64 × 3616 px**, проверен её последний пиксель. Консервативный лимит буфера обмена сохранён.
- Размеры из присланного пользователем JSON проверены на искусственных PNG-кадрах: обрезка **3817 × 5413** и оригинал **3817 × 10190**, каждый в **PNG и JPEG**. Каждый клик «Сохранить» вызывает ровно одну загрузку. Все 4 файла декодированы нативным `createImageBitmap`, проверены размеры; у PNG проверены пиксели до/после стыков кадров, на бывшей границе частей и справа/внизу. Сами изображения пользователя в JSON отсутствуют и не восстанавливались из него.
- Реальный захват страницы с шириной **2400 CSS px** и высотой **3500 CSS px**, сетка по двум осям, правильные пиксели слева/на швах/справа и восстановление горизонтальной прокрутки.
- На `chrome://version` выдаётся понятная ошибка, инъекция не выполняется.
- Нет непойманных ошибок JS редактора.
- Восемь размеров окна (590–1600 CSS px), смена доступного места/полос прокрутки и масштаб «По ширине»: правильная ширина изображения, доступная кнопка очистки, стабильные размеры на 12 последовательных кадрах. Ошибки ResizeObserver не подавляются; они попали бы в общий список непойманных ошибок.
- Полная очистка во время экспорта при нескольких открытых редакторах. Искусственно добавлены кадр без метаданных, Cache Storage, localStorage/sessionStorage. После команды у каждого редактора нет Canvas, отключено сохранение, заголовок страницы сброшен. `indexedDB.databases()` и `caches.keys()` возвращают пустые списки, web storage пуст. Отслежено явное удаление Blob URL; незавершённый экспорт не запускает скачивание. Уже скачанные файлы теста остаются на диске. Декодирование изображения замедлялось только в памяти тестовой вкладки для воспроизводимого незавершённого экспорта.
- Открытие прежнего ID после удаления не возвращает снимок. Библиотека пуста; отдельная кнопка очистки буфера успешно выполняет `clipboard.writeText("")`. Содержимое буфера не считывалось: разрешение на чтение не добавлялось.
- Повторная очистка из библиотеки также удаляет базу, включая пустую базу, созданную при открытии библиотеки.
- Полная очистка отменяет активный захват без переключения исходной вкладки: восстановлены прокрутка/CSS/атрибуты lazy images, через секунду база по-прежнему отсутствует, не появляется новая вкладка с ошибкой/снимком. Следующий полноценный захват успешно открывается с превью. После его повторной очистки база опять отсутствует.

## Что ещё проверить вручную

Автоматизация запускала action через протокол Chrome. Нативное меню пазла, ручная установка в основном профиле пользователя и взаимодействие с интерфейсом Chrome физической мышью этим тестом не проверялись.

**Windows непосредственно не запускалась.** Проверка численных случаев Windows и дробного масштаба выполнялась алгоритмами и в Chrome на macOS. На macOS headless не удалось принудительно получить нативную классическую полосу прокрутки: браузер сохранил overlay-вариант. Случаи с отдельным gutter проверены unit-тестами; обычный Chrome Windows с масштабом экрана 150% нужно повторно проверить на ПК пользователя.

1. Загрузить папку через `chrome://extensions`, закрепить иконку и нажать её на обычной статье/документации. Пройти полный путь «иконка → снимок → Crop → PNG/JPEG → открыть сохранённый файл».
2. Перетянуть каждый из восьми маркеров, пересечь противоположную границу, подвигать выделение, проверить автопрокрутку при выделении длинного участка. Нажать Отмена, затем сделать несколько последовательных обрезок и Сбросить.
3. Вставить скопированный PNG в выбранное приложение. Автотест проверял успешную запись, а не вставку в стороннее приложение.
4. Проверить нативные мониторы DPR 1, 2 и 3, зум Chrome 80/90/110/150/200%, очень узкое окно, вертикальные и горизонтальные полосы прокрутки. Не менять масштаб во время захвата.
5. На реальном сайте с медленной сетью убедиться, что lazy images успевают загрузиться. Отдельно проверить cookie-баннеры, sticky таблицы, анимации, изображения с нестандартным custom lazy loading.
6. Отменить панелью страницы, повторным нажатием иконки, колесом, переключением вкладки и навигацией; поменять размер окна во время захвата. Убедиться в восстановлении и понятной ошибке.
7. Во время захвата принудительно остановить service worker через DevTools, затем подождать до 17 секунд на живой исходной вкладке. Проверить восстановление watchdog. Принудительное закрытие всего процесса Chrome не позволяет никакому JS выполнить восстановление.
8. Проверить загрузку всех частей в обычном интерфейсе Chrome, в том числе системное разрешение на несколько скачиваний; скачать JSON-карту и сопоставить координаты. Автотест проверял отдельную последнюю часть, а не системный диалог множественных загрузок.
9. В библиотеке открыть старый снимок, удалить снимок и проверить освобождение хранилища. Проверить ограничение дисковой квоты, нехватку памяти, лимиты времени/600 кадров и очистку снимков старше суток. Эти ресурсные аварии не имитировались автоматически.
10. При необходимости включить доступ к `file://` и проверить локальную HTML-страницу. Встроенный PDF viewer и Chrome Web Store относятся к ограничениям Chrome; это не поддерживаемые обычные документы.
11. На Windows при масштабе экрана 150% открыть длинный снимок, несколько раз изменить размер окна, зум просмотра и Crop. Проверить отсутствие новых сообщений ResizeObserver в `chrome://extensions`. Старые сообщения очистить в журнале Chrome отдельно. На macOS автоматизация меняет 8 размеров viewport; это не заменяет нативные полосы прокрутки Windows.
12. Нажать «Очистить всё», проверить все открытые редакторы и пустую библиотеку. Затем сделать новый снимок. Вставкой в стороннее приложение проверить отдельную кнопку очистки буфера. История буфера Windows (Win+V), скачанные файлы, история/журнал ошибок Chrome и физическое освобождение RAM/дисковых блоков не управляются этим расширением и не проверяются как удалённые.

Вложенные скроллеры, раскрытие iframe, виртуализированные списки и аннотации не входят в эту версию. Их развитие отдельно предложено в README.
