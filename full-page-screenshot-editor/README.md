# Full Page Screenshot Editor

Готовое локальное расширение Chrome на Manifest V3. Нажатие на иконку запускает захват всей обычной веб-страницы. Результат открывается в тёмном редакторе с обрезкой и экспортом. Сервер, аккаунт, облако и сборка не нужны.

## Обновление 1.0.3: полная очистка и исправление ResizeObserver

Вверху редактора появилась кнопка **«Очистить всё»**. Одно нажатие удаляет все снимки и данные расширения. Та же команда доступна через **Снимки → Удалить все снимки и данные**. Она работает и без открытого изображения, при ошибке, во время экспорта и во время другого захвата.

Очистка блокирует новые захваты, отменяет текущий и дожидается восстановления исходной страницы. Затем все открытые редакторы освобождают превью и Blob-ссылки, прерывают экспорт и перезагружаются в пустое состояние. Удаляется целиком база IndexedDB: оригинальные PNG-кадры, записи снимков, заголовки/URL страниц, ошибки, диагностика, незавершённые сеансы и кадры без метаданных. Также очищаются localStorage, sessionStorage открытых редакторов и Cache Storage расширения; сейчас обычная работа в них ничего не записывает. Повторная запись из отменённого захвата исключена. Новый снимок после очистки работает как обычно.

В библиотеке есть отдельная кнопка **«Очистить буфер обмена»**: она заменяет его текущее содержимое пустым текстом, даже если вы скопировали его из другого приложения. При полной очистке без этой кнопки системный буфер сохраняется. **Уже скачанные PNG/JPEG/JSON остаются в выбранных папках** — удаляйте их через Проводник/Finder. Расширение не имеет доступа к произвольным файлам компьютера.

Закрытие редактора по-прежнему сохраняет оригинал в библиотеке. Превью, активные задачи и Blob-ссылки освобождаются при закрытии; постоянные данные удаляются кнопкой очистки. Обрезка хранится как координаты в памяти вкладки, отдельная копия изображения в IndexedDB не создаётся. Редактор не сохраняет историю обрезок или настройки между открытиями.

Освобождение ссылок и удаление базы не гарантируют моментального уменьшения потребления RAM процессом Chrome или физического затирания дисковых блоков: выделением памяти, сборкой мусора и файлами профиля управляют Chrome и ОС. История/журнал ошибок Chrome, резервные копии системы и история буфера обмена Windows также находятся вне хранилища расширения. Кнопка удаляет все данные, которые хранит само расширение, без обещания полного отсутствия системных следов.

Сообщение **`ResizeObserver loop completed with undelivered notifications`** означает, что пересчёт размеров интерфейса снова изменил наблюдаемый размер и Chrome отложил часть уведомлений. В старом коде обработчик наблюдателя напрямую вызывал layout. Теперь изменения планируются через `requestAnimationFrame`, одинаковые размеры пропускаются, а место под полосу прокрутки зарезервировано. Сообщение не подавляется обработчиком ошибок. [Описание механизма ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver#observation_errors).

Для обновления замените файлы **в той же установленной папке**, нажмите «Перезагрузить» на карточке в `chrome://extensions` и обновите/закройте старые вкладки редактора. Версия на карточке — **1.0.3**. Ранее записанное сообщение в разделе «Ошибки» Chrome можно удалить его кнопкой «Удалить все»: эта кнопка очищает журнал ошибок, а не снимки.

## Обновление 1.0.2: одно изображение вместо обязательных частей

**«Сохранить» по умолчанию создаёт один файл.** Для большого PNG используется сборка небольшими полосами и потоковое deflate-сжатие внутри Chrome, поэтому Canvas размером со весь снимок не нужен. Размеры и пиксели оригинала сохраняются. Кнопка **«Частями»** остаётся дополнительным ручным вариантом.

Проверены размеры из присланного `screenshot-parts.json`: выбранная область **3817 × 5413 px** и полный оригинал **3817 × 10190 px** экспортируются одним PNG и одним JPEG. Если нужна вся исходная страница после обрезки, нажмите **«Сбросить»**, затем **«Сохранить»**. JSON содержит только карту размеров и координат; сами изображения в нём не находятся.

Обновляйте файлы **в той же установленной папке**, включая `lib/png.js` и `lib/export.js`. Затем нажмите «Перезагрузить» в `chrome://extensions` и обновите вкладку редактора. Удалять расширение не нужно: при сохранении той же установки существующие снимки в IndexedDB доступны через «Снимки». Подтверждённые обрезки между закрытиями редактора не сохраняются.

## Обновление 1.0.1: дробный масштаб Windows

Исправлена ошибка «Не удалось согласовать границы кадра с изображением» при округлении размеров viewport и PNG, в том числе для масштаба экрана 150%. Масштаб DPR используется, если фактические размеры кадра подтверждают его по обеим осям. Склейка проверяет фактические пиксельные границы каждого PNG и покрытие сетки. Внешняя граница может отличаться от CSS-оценки на несколько пикселей округления; это учитывается без растягивания изображения. Значительные пропуски по-прежнему приводят к ошибке.

Исправление входит и в 1.0.2. При обновлении с 1.0.0 включите новый `lib/stitch.js` и обновите исходную веб-страницу. Изменять масштаб Windows для работы исправления не требуется.

Если захват всё ещё завершится ошибкой, в редакторе доступна кнопка «Скачать диагностику». JSON содержит версию, данные браузера и численные размеры кадра/viewport; снимки и URL страницы в этот файл не включаются.

## Установка

1. Откройте `chrome://extensions` в Google Chrome 110 или новее.
2. Включите **Режим разработчика / Developer mode**.
3. Нажмите **Загрузить распакованное расширение / Load unpacked**.
4. Выберите **эту папку `full-page-screenshot-editor`**, где находится `manifest.json`.
5. Закрепите расширение через меню пазла на панели Chrome.

После изменения исходников нажмите кнопку перезагрузки на карточке расширения. Для тестирования `file://` отдельно включите «Разрешить доступ к URL файлов» в его настройках.

## Использование

1. Откройте обычную HTTP(S)-страницу и дождитесь загрузки.
2. Нажмите иконку расширения. Во время предзагрузки и захвата видны панель прогресса и процент на иконке. Не меняйте размер окна, зум или активную вкладку.
3. Для отмены нажмите **Esc**, **Отменить** на странице или повторно иконку. Попытка прокрутить страницу вручную также отменяет захват. Переключение вкладки прекращает захват, чтобы не включить чужую вкладку в изображение.
4. После захвата автоматически откроется `editor.html` с полным изображением. При отмене открывается неактивная вкладка с пояснением.
5. Нажмите **Обрезать / C**, выделите прямоугольник мышью. Перемещайте его целиком или тяните за восемь маркеров. У края окна выделение автоматически прокручивается.
6. При необходимости введите X, Y, ширину и высоту в пикселях оригинала. Стрелки сдвигают область на 1 px, Shift + стрелки — на 10 px.
7. **Применить / Enter** подтверждает обрезку, **Отмена / Esc** отменяет текущее выделение. **Сбросить** возвращает полный оригинал. Можно обрезать несколько раз.
8. Выберите PNG или JPEG и нажмите **Сохранить**. **Копировать PNG** помещает выбранную область в системный буфер. Сохранение/копирование использует текущее выделение, если оно ещё не подтверждено; иначе — результат обрезки или оригинал.

Масштаб просмотра меняется кнопками −/+, списком или Ctrl/Cmd + колесо. Он не влияет на экспорт. Значение **100%** означает один пиксель снимка на один CSS-пиксель редактора. На Retina физические пиксели экрана и CSS-пиксели могут различаться.

## Большие изображения

Исходник не уменьшается. В IndexedDB хранятся PNG-кадры видимой области и небольшая карта их координат. Полная страница представлена логически. Редактор рисует только видимую область. Большой PNG собирается небольшими полосами: временный Canvas не шире 8192 px и не выше 256 px, RGB-буфер полосы обычно до 4 МиБ. Полосы сжимаются одним потоком и записываются в IDAT-блоки **одного PNG**. Полный RGBA-буфер страницы не выделяется; итоговый сжатый Blob всё же занимает память.

JPEG использует нативный Canvas-кодировщик: в версии 1.0.2 разрешён один файл до **32767 px по стороне** и **64 мегапикселей**. На слабом устройстве может не хватить памяти; для более крупных областей выберите PNG. Расширение не уменьшает изображение автоматически. Просмотр очень длинного PNG также зависит от возможностей выбранной программы просмотра.

При нажатии **«Частями»** применяются прежние консервативные границы: **8192 px по стороне** и **16 777 216 пикселей** на часть. Справа появятся отдельные загрузки, «Скачать все части» и JSON-карта координат. При массовой загрузке Chrome может запросить разрешение на несколько файлов. Буфер обмена сохраняет этот консервативный бюджет; для большей области используйте сохранение одним файлом.

Описание потоковой упаковки: [PNG specification](https://www.w3.org/TR/png-3/) и [CompressionStream](https://developer.mozilla.org/en-US/docs/Web/API/CompressionStream). Сжатие выполняется локально, без зависимостей и сетевых запросов.

Память не бесконечна: действует явный лимит 600 кадров, 512 МиБ сжатых кадров и 4 минуты на сеанс; предзагрузка ограничена минутой. При превышении выдаётся ошибка, а неполный снимок не выдаётся за полный. Нехватка квоты IndexedDB и ошибки Canvas показываются пользователю. При нехватке памяти выберите меньшую область и закройте лишние вкладки.

## Разрешения и приватность

- `activeTab` — временный доступ к вкладке после нажатия на иконку.
- `scripting` — внедрение управляющего content script только в эту вкладку.
- `clipboardWrite` — запись PNG в буфер из редактора.

Нет `tabs`, `downloads`, `storage`, `unlimitedStorage`, постоянных host permissions, `debugger`, внешних библиотек или внешних ресурсов. Загрузка файлов идёт через локальную Blob-ссылку. Скриншоты, заголовок и URL страницы сохраняются только в IndexedDB расширения; изображения не передаются через runtime-сообщения или `chrome.storage.local`. Расширение не отправляет сетевые запросы к серверам. Прокрутка исходной страницы может запускать её собственные запросы lazy loading.

Кнопка **Снимки** открывает локальную библиотеку и позволяет удалить любой снимок. **Очистить всё** удаляет всю базу и сбрасывает все редакторы; точный состав очистки и её границы описаны выше. Закрытие редактора не удаляет оригинал: его можно открыть снова через библиотеку. Снимки старше 24 часов удаляются при следующем захвате. Это очистка по использованию, а не фоновый таймер. Удаление расширения удаляет его хранилище.

## Как устроен захват

1. `background.js` внедряет `content.js` через `chrome.scripting`, сохраняет метаданные сеанса и запускает предзагрузку.
2. Content script сохраняет позицию прокрутки, изменяемые CSS-свойства с их приоритетами и атрибуты lazy-изображений. Отключает smooth scroll, snap, scroll anchoring, переходы и анимации; sticky временно возвращает в поток. Страница последовательно прокручивается, видимые изображения получают ограниченное ожидание `decode()`, шрифты — `fonts.ready`.
3. После предзагрузки размеры фиксируются. План кадров покрывает обе оси с перекрытием 64 CSS px, включая остаток внизу и справа. Fixed-элементы видны только в первом кадре; остальные кадры снимаются с их скрытой видимостью. Для добавленных DOM-элементов работает MutationObserver.
4. Вызовы `chrome.tabs.captureVisibleTab()` начинаются с интервалом не менее **650 мс**. Это ниже лимита Chrome в два вызова в секунду. Перед/после снимка проверяются активная вкладка, позиция, размер окна и масштаб.
5. `devicePixelRatio` сверяется с фактическими размерами PNG по обеим осям, включая варианты с обычными полосами прокрутки. При совпадении используется этот стабильный масштаб; иначе — согласованный масштаб, измеренный по PNG и viewport. Для обеих осей масштаб одинаковый: округление отдельного viewport не накапливается по длинной странице. Дробные размеры берутся из `visualViewport`, где это возможно. Склейка использует фактические координаты прокрутки и допустимые пиксельные области каждого кадра. Внешний край допускает ограниченное округление, внутри сетки обязательно сплошное покрытие без пропусков. Пиксели исходников не растягиваются.
6. Blob каждого кадра сразу записывается в IndexedDB. После успеха, ошибки и отмены блок `finally` восстанавливает исходную страницу. Дополнительно content script восстанавливает её при `pagehide` или потере связи на 15 секунд (проверка каждые 2 секунды). Если браузер приостановил вкладку целиком, восстановление выполнится после возобновления её JS.
7. Новая вкладка редактора читает данные напрямую из IndexedDB. Все координаты Crop — целые пиксели оригинала. Виртуальное превью может быть уменьшено для экрана; файлы собираются с масштабом 1:1.

Источники API: [captureVisibleTab и его лимит](https://developer.chrome.com/docs/extensions/reference/api/tabs), [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [жизненный цикл MV3 worker](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle). Каждый кадр вызывает API расширения, но неожиданное завершение worker всё равно возможно; поэтому кадры сохраняются постепенно, а content script имеет собственное восстановление. Прерванный сеанс не возобновляется автоматически.

## Проверки

Для работы расширения Node.js не нужен. Для разработки нужен Node.js 20+:

```sh
npm run check
npm test
npm run build
```

`build` проверяет готовые исходники: транспиляции нет. Проверяются manifest и минимальные разрешения, локальные ресурсы, синтаксис JavaScript, ссылки на HTML-элементы и отсутствие inline script. Тесты проверяют план кадров и края страницы, дробный DPR и швы, отображение обрезки между кадрами, изменение границ, точность координат при зуме, разделение огромных изображений без пропусков/перекрытий и частоту захвата.

Необязательный интеграционный тест требует Playwright и Chrome с CDP `Extensions.loadUnpacked` / `Extensions.triggerAction` (новые версии Chrome):

```sh
npm install --no-save --package-lock=false playwright
CHROME_PATH="/path/to/chrome" npm run test:browser
# Или установленный Playwright Chromium: npx playwright install chromium
# npm run test:browser
```

Тест использует **реальный неизменённый manifest**, отдельный временный профиль и HTTP-сервер на `127.0.0.1`. Никакие разрешения для теста в расширение не добавляются. Если Playwright установлен вне проекта, задайте `PLAYWRIGHT_MODULE` как абсолютный путь к `playwright/index.mjs`. `HEADED=1` включает видимое окно. Отчёт — `test-results/browser-report.json`, PNG редактора и примеры экспорта — в `test-results`. Эти средства разработки в runtime расширения не используются.

Фактически выполненные проверки и оставшиеся ручные проверки описаны в [TESTING.md](TESTING.md).

## Границы минимальной версии

- Поддерживается прокрутка **основного документа**, в том числе обычные длинные страницы с горизонтальным переполнением. Вложенные независимые скроллеры, виртуализированные списки и cross-origin iframe не разворачиваются; iframe снимается в его текущем видимом состоянии.
- `chrome://`, Chrome Web Store, встроенный PDF viewer и другие защищённые страницы запрещают нужную инъекцию. На них показывается понятная ошибка.
- Обычный зум Chrome поддерживается. Жестовый pinch zoom нужно сбросить перед захватом.
- Нельзя получить полностью согласованный снимок непрерывно изменяющегося сайта. Если геометрия изменилась после предзагрузки, захват останавливается с пояснением, чтобы не сохранить неполную склейку.
- Предзагрузка изображений ограничена временем. Очень медленные изображения, видео, WebGL, реклама и анимации внутри закрытых shadow roots могут выглядеть иначе. Shadow DOM и fixed/sticky внутри iframe не нормализуются.
- Fixed-элементы сохраняются в первом кадре в позиции viewport. Поэтому fixed-баннер внизу окна попадёт в верхнюю часть итогового документа. Sticky возвращается в естественный поток; на сложных CSS-layout это может изменить вид страницы. Все эти изменения затем восстанавливаются.
- Квота IndexedDB зависит от устройства и профиля. Исчезновение/очистка локальных кадров приводит к сообщению об ошибке, а не пустому экспорту.
- Выгруженный/принудительно остановленный процесс браузера не способен выполнить JS-восстановление; обычная навигация, ошибки и отмена обрабатываются. Если вкладка продолжает жить после остановки worker, работает watchdog.

## Отдельные дальнейшие улучшения

1. **Сложные сайты:** настройки ожидания, повторный проход проверки геометрии, обнаружение перекрывающих баннеров, опциональное отключение обработки fixed/sticky, обход открытых shadow roots, возобновление после остановки worker.
2. **Вложенные скроллеры:** выбор контейнера пользователем, отдельный план его прокрутки и локальная склейка с восстановлением `scrollTop/scrollLeft`. Виртуализированные списки требуют отдельной стратегии повторного рендеринга; для iframe нужны отдельные ограниченные разрешения.
3. **Аннотации:** независимые векторные слои со стрелками, прямоугольниками, текстом, размытием и undo/redo; применение слоёв при экспорте каждой части в исходных координатах.
4. **Экспорт:** локальный ZIP с потоковой записью частей и картой, настройка бюджета памяти и JPEG quality, дополнительные форматы, история обрезок.

Эти улучшения не заявлены как уже реализованные функции версии 1.0.
